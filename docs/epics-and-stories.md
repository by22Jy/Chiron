# YOLO-LLM Epics and User Stories

## 优先级策略

**P0 - 关键Bug修复** - 修复现有功能的核心问题，确保系统稳定性
**P1 - 功能增强** - 改进现有能力，提升用户体验
**P2 - 新功能开发** - 基于现有模式添加新功能

---

## Epic 1: 语音控制核心功能修复 (P0)

**概述**: 修复语音控制系统中影响用户使用的关键问题，确保基础功能稳定可靠

### User Story 1.1: 语音识别服务连接稳定性修复
**优先级**: P0
**作为** 用户，**我想要** 语音识别服务能够稳定连接和断线重连，**以便** 系统不会因为网络波动而无法使用语音控制

**接受标准**:
- [ ] 实现自动重连机制，网络恢复后自动重连语音识别服务
- [ ] 添加连接状态监控，实时显示连接状态
- [ ] 添加超时处理，避免长时间等待导致系统无响应
- [ ] 错误时提供清晰的错误信息和解决建议

**相关文件**: `agent/speech_controller.py`, `ai/main.py`

### User Story 1.2: 智能控制器JSON解析异常处理
**优先级**: P0
**作为** 用户，**我想要** 当LLM返回格式不正确的响应时，系统能优雅处理而不是崩溃，**以便** 语音控制功能稳定运行

**接受标准**:
- [ ] 增强JSON解析错误恢复机制
- [ ] 添加响应格式验证和清理
- [ ] 实现多种解析策略作为后备方案
- [ ] 记录详细的解析错误日志用于调试

**相关文件**: `agent/intelligent_controller.py`

### User Story 1.3: MCP工具集成错误处理
**优先级**: P0
**作为** 用户，**我想要** MCP工具调用失败时系统能优雅降级，**以便** 即使部分工具不可用，核心功能仍能正常工作

**接受标准**:
- [ ] 实现MCP工具健康检查机制
- [ ] 添加工具调用失败时的备用方案
- [ ] 提供工具状态监控和报告
- [ ] 优化错误信息，提供用户友好的反馈

**相关文件**: `backend/LLMController.java`, `mcp/core/mcp_server.py`

### User Story 1.4: 邮件参数映射逻辑修复 (关键问题)
**优先级**: P0
**作为** 用户，**我想要** 系统能正确提取邮件专用参数(to, subject, content)而不是发送通用的action=execute参数，**以便** 邮件发送功能正常工作

**接受标准**:
- [ ] 修复`AiOrchestratorService.java`中的参数提取逻辑
- [ ] 实现从LLM分析中提取邮件专用参数的方法
- [ ] 验证邮件工具调用使用正确的参数格式
- [ ] 测试"发送邮件给xxx，主题yyy，内容zzz"命令成功执行

**相关文件**: `backend/src/main/java/com/example/aiorchestrator/service/AiOrchestratorService.java`

### User Story 1.5: MCP服务器启动修复
**优先级**: P0

## 实施建议 (基于深层集成分析)

### 第一阶段 (1-2周) - 关键集成修复
**优先级最高的P0修复，解决您最关注的agent-backend联调问题:**
- **User Story 1.4**: 邮件参数映射逻辑修复 (解决邮件发送失败的核心问题)
- **User Story 1.5**: MCP服务器启动修复 (确保MCP工具正常工作)
- **User Story 1.6**: 数据流标准化修复 (统一agent-backend数据格式)
- **User Story 1.10**: 邮件客户端集成逻辑修复 (统一邮件工作流)
- **User Story 1.9**: 服务发现和健康检查修复 (确保服务可用性)

### 第二阶段 (1-2周) - 深层逻辑修复
**解决日志中看不到的深层集成问题:**
- **User Story 1.7**: 状态管理和会话一致性修复

- **User Story 1.11**: LLM编排逻辑循环修复
- **User Story 1.12**: 多步骤工作流协调修复

### 第三阶段 (1-2周) - 功能增强和测试
**在稳定基础上进行功能验证和增强:**
- 实施P1功能增强(上下文感知、反馈机制等)
- 全面测试修复后的集成功能
- 收集用户反馈并持续优化
- 开始P2新功能开发

## 技术债务清理

在实施这些用户故事时，同时需要关注以下技术债务：

1. **日志系统统一** - 统一所有模块的日志格式和级别
2. **配置管理优化** - 集中化配置管理，避免硬编码
3. **错误码标准化** - 建立统一的错误码和错误消息体系
4. **性能监控** - 添加关键路径的性能监控
5. **测试覆盖率** - 提升核心功能的测试覆盖率

## 成功指标

- **稳定性**: 系统连续运行24小时无崩溃
- **响应速度**: 语音识别到命令执行平均时间 < 3秒
- **准确率**: 语音命令识别准确率 > 90%
- **恢复能力**: 服务异常后自动恢复成功率 > 95%
- **用户体验**: 用户满意度调查 > 4.0/5.0
